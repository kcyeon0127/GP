# 5분 시연 대본

시드 데이터는 합성한 가게(한결 식자재 납품)이고, 계약 근거는 공개 표준계약서 원문 조항에 금액·날짜만 채운 것이다. 실제 체결 계약서가 아니므로 시연에서 그렇게 말한다.

아래 숫자는 기준일 2026-11-07에서 잰 값이다. 기준일이 다르면 금액은 달라지지만 노랑→빨강 전환은 같다.

| 상태 | 시작 잔액 | 안전 잔액 | 신호 | 값 |
| --- | --- | --- | --- | --- |
| 시드 직후 | 10,520,000원 | 2,000,000원 | 노랑 | 11/11 최저 1,700,000원 |
| 한빛식자재 결제일 7일→21일 | 10,520,000원 | 2,000,000원 | 빨강 | 최초 부족일 11/09, 부족액 2,960,000원, 최저 -8,100,000원 |

## 실행 준비 체크리스트

시연 30분 전에 차례로 확인한다.

- [ ] Docker Desktop 실행 후 `docker compose up -d` (PostgreSQL, Neo4j)
- [ ] SSH 터널: `ssh -N -L 8101:127.0.0.1:8101 lab`
- [ ] `backend/.env`에 `EMBEDDING_API_KEY` 있음
- [ ] 시드: `cd backend && .venv/bin/python -m scripts.seed_demo` 를 돌려 마지막 줄이 `YELLOW`인지 본다
- [ ] 백엔드: `.venv/bin/uvicorn app.main:app --port 8000`
- [ ] 프론트: `cd frontend && npm run dev` 후 http://localhost:5173
- [ ] 리허설로 결제일을 고쳤다면 시드를 다시 돌려 노랑으로 되돌린다

**기준일 주의.** 기준일 기본값은 오늘이다. 다만 오늘이 매월 8~21일이면 결제일을 21일로 고칠 때 다음 입금일이 오히려 앞당겨져 빨강이 되지 않으므로, 시드가 기준일을 그달 7일로 당기고 안내를 출력한다. 이때 화면의 기준일은 오늘이 아니라 그달 7일이다. 발표 날짜가 정해져 있으면 `--base-date 2026-11-07`처럼 고정해도 된다. 22일~다음 달 7일 사이 날짜를 쓴다.

## 대본

### 1. 내 거래·일정 (40초)

- 클릭: 왼쪽 메뉴 **내 거래·일정**
- 말: "소규모 식자재 납품 가게입니다. 거래처 정산과 매입 대금, 임대료·4대보험·카드대금·부가세, 대출 상환까지 등록해 두면 앞으로 12주 일정이 자동으로 만들어집니다."

### 2. 홈: 노랑 (40초)

- 클릭: 왼쪽 메뉴 **홈**. 신호 카드를 눌러 영향 일정을 연 뒤 다시 닫는다.
- 말: "지금 자금 상태는 주의입니다. 부족하지는 않지만 안전 잔액 200만 원 아래로 내려가는 날이 있고, 어떤 일정 때문인지 바로 볼 수 있습니다."

### 3. 한빛식자재 결제일 수정 (40초)

- 클릭: **내 거래·일정** → 거래처 목록 **한빛식자재**의 **수정** → 결제일을 `21`로 → **수정 저장**
- 말: "가장 큰 거래처 정산이 2주 늦어진다는 연락을 받았다고 하겠습니다. 결제일만 7일에서 21일로 바꿉니다."

### 4. 홈: 빨강, 부족일, 부족액 (50초)

- 클릭: 왼쪽 메뉴 **홈**
- 말: "신호가 위험으로 바뀌었습니다. 대성유통 대금이 나가는 11월 9일에 잔액이 0원 아래로 내려가고, 296만 원이 모자랍니다. 사장님은 2주 전에 이 사실을 알게 됩니다."

### 5. 이유 보기 (70초)

- 클릭: **왜 자금 상태가 "위험"일까요?** 카드의 **이유 보기**
- 말: "P는 거래관계 경로, D는 계약 문서 조항입니다. 11월 9일 대성유통 매입 대금이 먼저 나가고, 한빛식자재 980만 원은 21일에야 들어옵니다. D에는 공정위 표준하도급계약서의 지연이자 조항 같은 근거가 함께 나옵니다. 금액은 계산 모듈이 낸 값이고, 조항은 공개된 표준계약서 원문입니다."

### 6. 내 등록 데이터 금융지도 (40초)

- 클릭: 왼쪽 메뉴 **원인 보기** → 오른쪽 위 **내 등록 데이터로 보기**
- 말: "방금 본 경로가 이 지도에 그대로 있습니다. 사업장을 가운데 두고 거래처, 계약, 고정비, 대출이 어떻게 이어지는지 볼 수 있습니다."

## 서버가 죽었을 때

| 증상 | 화면 | 대처 |
| --- | --- | --- |
| 터널·임베딩 서버만 끊김 | 이유 보기에 P만 나오고 "계약 문서 근거를 지금 불러오지 못해…" 문구 | 그대로 진행한다. "문서 근거는 연구실 서버에서 옵니다"라고 말하고, 터널을 다시 연결한 뒤 **다시 보기**를 누른다. |
| 시드 때 터널이 끊겨 있음 | 시드가 안내와 함께 멈춤. 기존 데이터는 유지됨 | 터널을 다시 연결하고 다시 돌린다. |
| 백엔드·DB가 죽음 | 새로고침하면 "서버에 연결되지 않아 합성 데이터 시연 화면을 보여 드려요" 배너 | 합성 모드로 넘어간다. "연결이 끊겨도 화면은 합성 데이터로 돌아갑니다"라고 말하고 홈 → 원인 보기(시연 지도) → 시나리오 순서로 보여 준다. 합성 모드의 숫자와 거래처 구성은 이 대본과 다르므로 대본의 금액을 말하지 않는다. 결제일 수정 장면은 건너뛴다. |
